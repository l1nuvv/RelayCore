# План автоматизации выпусков и обновлений — 28 сентября 2026

Основание: пять замечаний автора после выпуска 1.3.1. Этот документ содержит согласованный запрос на реализацию; общая очередь проекта остаётся в PLAYABLE_SLICE_ROADMAP.md.

## Оценка и выбранное решение

Идея реализуема без своего сервера. Локальная команда готовит выпуск, GitHub Releases хранит версии, игрок получает обновление из меню. Старые опубликованные файлы не заменяются: каждый номер обозначает один неизменяемый ZIP. Полная замена папки после проверки убирает устаревшие файлы и сохраняет предыдущую установку.

Для нынешнего архива около 22 МБ сохраняем полную загрузку ZIP. Дельта-патчи добавили бы отдельные форматы, зависимость от исходной версии и дополнительные сценарии отказа; их стоит вводить только после замеров загрузки существенно выросших сборок. Быстрота здесь — минимум действий автора, отсутствие ненужных пересборок, проверенная загрузка и понятный интерфейс.

Осмысленное описание нельзя достоверно получить из списка имён файлов. Изменения сопровождаются короткими записями для игрока; скрипт автоматически группирует их и оформляет Markdown для GitHub и обычный текст для игры. При выполнении задач эти записи обновляет разработчик или работающий над задачей ассистент. Отдельный платный ИИ-сервис для выпуска не требуется; выдуманные улучшения в описание не попадают.

## Задачи и критерии готовности

| ID | Приоритет | Работа | Проверка готовности | Статус |
| --- | --- | --- | --- | --- |
| U-001 | P0 | Один источник текущей версии, автоматический patch/minor/major, передача версии в CMake, меню и updater | Подготовка выпуска меняет версию согласованно; ошибочный номер отклоняется; история старых выпусков не переписывается | done |
| U-002 | P0 | Одна команда подготовки: окружение VS, версия, описание, Release, проверки, ZIP, зафиксированный кандидат; отдельная явная публикация готового кандидата | Повтор после ошибки не увеличивает номер второй раз; публикация сверяет точный ZIP и заметки; токены не попадают в игру | done |
| U-003 | P0 | Проверка → описание → установка → закрытие игры → перезапуск → уведомление об установленной версии | Уведомление появляется только после запуска через updater; обычный запуск его не показывает; сбой не выдаётся за успех | done |
| U-004 | P1 | Использовать Release с оптимизацией и без Tracy для раздачи; сохранить Debug/профилирование; измерить первый и повторный сборочный проход | Release собирается и проходит приёмку; записаны реальные длительности, нет обещаний ускорения FPS без профиля | done |
| U-005 | P0 | Проверки генератора, негативных сценариев updater, графического меню, реальной упакованной игры; документация одной команды | Все команды и результаты зафиксированы; публичный выпуск выполняется после разрешения на конкретный готовый кандидат | done |

## Порядок и границы

1. Выполнить U-001 и U-002: сначала сделать воспроизводимую подготовку выпуска.
2. Выполнить U-003 и проверить уведомление после реального перезапуска.
3. Выполнить U-004 на существующих пресетах, затем U-005.
4. Перед публикацией показать точную версию, ZIP и описание и получить разрешение автора, как он потребовал ранее.

Сохранения и настройки не переносятся в папку игры и не удаляются. Не изменять безопасность Windows, не требовать администратора, не устанавливать новые зависимости без необходимости. Не добавлять свою серверную инфраструктуру, постоянный фоновый процесс или автоматическую загрузку при каждом запуске. Производительность игрового кадра — отдельные измерения на воспроизводимом сценарии; сборочная оптимизация сама по себе не доказывает прирост FPS.

### Результат 28 сентября

С отдельного разрешения автора опубликована [1.3.2](https://github.com/l1nuvv/RelayCore-releases/releases/tag/v1.3.2). ZIP `build/playtest/RelayCore-playtest-20260928-114145-385.zip`: 94 файла, 21 879 488 байт, SHA256 `8D5984210FA8C3AFE5BBEEEEA60FC10FAD1EE0DF0E49F59D637C5D00A8B52DFD`. Исходники не коммитились и не отправлялись в удалённый репозиторий.

Изменения:

- `VERSION` — исходный номер; `scripts/release.ps1` автоматически увеличивает его и синхронизирует `vcpkg.json`. CMake читает VERSION и генерирует `game_version.h`/`updates.json`; меню использует сгенерированный заголовок. Исторические номера остаются историческими.
- `release/changes.json` и `scripts/release-functions.ps1` формируют короткий Markdown с непустыми разделами. В `release.json` для игры заголовки и пункты преобразуются в обычный текст.
- `scripts/release.ps1` готовит проверенный Release-кандидат и записывает его хеши/время этапов. `-Publish` публикует только этот кандидат. Блокировка файла исключает одновременные выпуски; повтор незавершённой подготовки не увеличивает номер снова; повтор уже выполненной публикации не создаёт новый релиз.
- `scripts/publish-release.ps1` умеет продолжить совпадающий черновик и распознать совпадающую законченную публикацию; файлы существующего другого релиза не заменяются.
- В игре появляется компактное подтверждение с версией и кнопкой «Понятно», совместимое со старым updater. После успешного запуска новый помощник закрывается автоматически. При 960×540 сообщение не вытесняет кнопку выхода за пределы окна.
- `scripts/package-playtest.ps1 -Preset msvc-release` пакует Release; прежняя упаковка RelWithDebInfo сохраняется для профилирования. Перед упаковкой сверяется версия build с VERSION.
