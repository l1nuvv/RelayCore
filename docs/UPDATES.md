# Обновления RelayCore для Windows

В standalone-сборках начиная с 1.3.0 главное меню показывает версию и кнопку «Проверить обновления». Проверка выполняется в фоне; игра работает без сети. Для установки игрок нажимает «Обновить и перезапустить»: настройки сохраняются, игра закрывается, отдельный `RelayCoreUpdater.exe` скачивает полный архив и показывает прогресс. Проверяется размер и SHA256 из опубликованного `release.json`, затем SHA256 каждого файла из `BUILD_MANIFEST.json`. Игра запускается вновь и подтверждает готовность после загрузки интерфейса. При ошибке замены или запуска установщик возвращает предыдущую папку, если её не блокирует оставшийся процесс.

Канал: `l1nuvv/RelayCore-releases`, только обычные опубликованные релизы `vMAJOR.MINOR.PATCH`, файлы `RelayCore-win-x64.zip` и `release.json`. Последняя версия определяется через `/releases/latest/download/release.json`, без анонимного GitHub API и его лимита запросов. Для установки используется manifest конкретной выбранной версии. Черновики и prerelease не устанавливаются. Проверка никогда не понижает версию. Канал задаётся CMake-параметром `RELAYCORE_UPDATE_REPOSITORY`; итоговые версия и канал попадают в `updates.json`. Раздача должна быть публичной; ключи доступа не входят в игру. Доверие обновления опирается на HTTPS и контроль владельца репозитория; отдельной цифровой подписи исполняемых файлов пока нет. Публикация канала требует отдельного согласования с автором.

Сохранения и настройки хранятся через существующий SDL user-data path, отдельно от папки игры. Установщик их не переносит и не удаляет. Новые релизы обязаны сохранять совместимость save format 3 либо содержать проверенную миграцию. Пользовательские изменения внутри папки игры остаются в резервной копии, но автоматически в новую сборку не переносятся.

Сборка должна быть распакована в обычную доступную для записи папку. Исходный checkout, папки через junction/symlink и запуск непосредственно внутри ZIP не поддерживаются. Установщик не запрашивает повышение прав и не меняет настройки безопасности Windows. На клиенте используется штатный .NET Framework Windows 11; PowerShell и .NET SDK для обновления не требуются. Сборка помощника использует установленный Windows `csc.exe`.

Обновление сохраняет предыдущую папку рядом с текущей как `.previous-<id>`; её можно удалить вручную после проверки игры. Неудачная новая сборка остаётся как `.failed-<id>`. При отключении питания между двумя переименованиями папок резервная копия остаётся на диске: закройте процессы игры и верните ей прежнее имя либо заново распакуйте опубликованный ZIP. Этот редкий сценарий не требует удаления сохранений. Журнал ошибки помощника — `%LOCALAPPDATA%/RelayCore/updater/<id>/error.log`.

## Выпуск следующей версии

В CLion выберите сохранённую конфигурацию **RelayCore — Release** и нажмите **Run** (Shift+F10). Она запускает `scripts/release.ps1 -Release`: повышает patch, создаёт описание, собирает и проверяет Release, упаковывает игру и публикует выпуск в GitHub Releases. Дополнительный CMake-пресет или External Tool не нужен. Конфигурация использует обычный исполняемый файл PowerShell 7 из уже установленного runtime Codex. Псевдоним Microsoft Store и исполняемый файл внутри защищённой папки WindowsApps не проходят проверку интерпретатора CLion. На другой машине укажите путь к своему обычному `pwsh.exe` в поле Interpreter path.

Описание автоматически оформляется из `release/changes.json`; эти короткие записи обновляются вместе с изменениями проекта. Повторное нажатие после сбоя сборки сохраняет номер. После сбоя загрузки повтор публикует уже проверенный кандидат; изменения исходников для нового кандидата требуют повторной подготовки без `-Release`. Если этот список уже опубликован, кнопка сообщает об этом и ничего повторно не выпускает. Для следующей версии сначала обновите записи. Авторизация Git Credential Manager должна быть доступна, как и для отдельной публикации.

При необходимости подготовку и публикацию можно по-прежнему выполнить отдельно:

В 1.3.0 обнаружено ограничение длинного пути временной распаковки; 1.3.1 сокращает этот путь. Если старый установщик сообщает о слишком длинном пути, закройте игру и перенесите её папку ближе к корню диска либо распакуйте исправленную сборку вручную. Уже опубликованные архивы не заменяются.

1. При выполнении задач поддерживать `release/changes.json`: короткий заголовок, массивы `added`, `changed`, `fixed`. Записи описывают результат для игрока; пустые разделы не выводятся. Скрипт оформляет описание автоматически, но не выдумывает смысл изменений по именам файлов.
2. Из обычного PowerShell в проекте выполнить `pwsh -NoProfile -File scripts/release.ps1`. Visual Studio C++ и vcpkg должны быть установлены; скрипт сам находит VS и загружает окружение. `VCPKG_ROOT` используется существующий, при отсутствии — встроенный в найденную VS.
3. Команда увеличивает patch в `VERSION`, синхронизирует `vcpkg.json`, конфигурирует `msvc-release`, собирает игру и приёмочные тесты, проверяет контент/updater, упаковывает ZIP и проверяет установку/запуск настоящей игры во временной папке. Версия CMake, меню и `updates.json` получается из `VERSION`. Смена версии затрагивает сгенерированный заголовок меню, а не compile definitions всего игрового модуля.
4. Готовый кандидат и длительности этапов записываются в `build/release/candidate.json`, описание — `build/release/release-<version>.md`. Повтор подготовки до публикации использует тот же номер; после ошибки следует повторить команду. Для нового выпуска после публикации сначала обновить список реальных изменений. `-Bump Minor` или `-Bump Major` выбирает тип следующего выпуска; повтор незавершённого выпуска должен использовать тот же тип.
5. Проверить показанные ZIP и описание. Для публикации именно этого кандидата выполнить `pwsh -NoProfile -File scripts/release.ps1 -Publish`. Архив и описание сверяются с записанными SHA256; пересборка и новый номер на этом шаге не выполняются. Команда использует существующую авторизацию Git Credential Manager, ничего не коммитит и не отправляет исходники в Git.

Номер в исторических протоколах и заметках старых выпусков не переписывается. `README` ссылается на `/releases/latest`, поэтому новая публикация не требует правки его номера вручную. Запуск **RelayCore — Release** автором означает выпуск с публикацией; отдельное согласование внутри этой команды не требуется.

Для отдельной упаковки доступны `scripts/package-playtest.ps1 -Preset msvc-release` и прежний вариант по умолчанию `msvc-relwithdebinfo`. Последний остаётся для профилирования и диагностических плейтестов. Пользовательский выпуск через `release.ps1` всегда использует Release: unity build и IPO включены, Tracy выключен. Отладочные и профильные пресеты сохраняются. Изменения FPS без измеренного игрового профиля не заявляются.

Публикующий скрипт создаёт черновик, загружает архив и `release.json`, сверяет их GitHub SHA256 и только затем публикует релиз. После обрыва повтор продолжает тот же черновик, если описание и уже загруженные файлы совпадают; чужие или изменённые данные не перезаписываются. Уже опубликованный совпадающий выпуск распознаётся без повторной загрузки. Доступ к приватному репозиторию не меняется.

После подтверждённого запуска обновлённой игры помощник закрывается, а главное меню показывает «Игра обновлена до версии …» с кнопкой «Понятно». Номер берётся из запущенной игры. Обычный запуск не показывает уведомление; сохранять постоянный флаг в пользовательских данных не нужно. Уведомление совместимо с запуском через старый updater 1.3.1.

## Проверки

Новая версия сигнализирует updater-у готовность после успешного `DemoGame::on_render()` загруженной игровой сессии. Этот сигнал не зависит от `on_ui()` или доступности ImGui. Ошибка загрузки уровня, в том числе показанная в меню, не подтверждает успешный запуск новой версии. Сценарии с UI, без UI и с ошибкой startup зарегистрированы как `graphics.update_readiness.*`.

`pwsh -NoProfile -File tests/release_workflow_tests.ps1` проверяет полный сценарий кнопки в отдельной тестовой копии с имитацией сборки и публикации: ошибки сборки/тестов/запуска/загрузки, повтор без повышения номера, следующий выпуск, синхронизацию версии, описание и отклонение изменённого кандидата. Реальные выпуски и сеть этот тест не затрагивает. Генератор номера и описания отдельно проверяется через `pwsh -NoProfile -File tests/release_scripts_tests.ps1`.

- `cmake --build --preset tests-debug --target relaycore_updater_tests`
- `ctest --preset test-debug -R '^relaycore.updater$' --output-on-failure`
- `build/msvc-debug/tests/relaycore_updater_tests.exe <полный-путь-к-настоящему-ZIP>` — устанавливает сборку во временной папке, ждёт подтверждения от настоящей игры, проверяет отсутствие старых файлов и сохранность backup, затем штатно закрывает тестовую игру.
- `ctest --preset graphics-debug -R '^graphics.(game_lifecycle|power_restoration)$' --output-on-failure`

Автотесты проверяют сравнение версий, чужой канал/URL, prerelease, неверные SHA256/размеры, повреждённый payload, traversal и повторяющиеся пути ZIP, успешную замену без смешивания старых файлов и rollback при отказе запуска. Установка с GitHub дополнительно проверяется после разрешённой публикации; локальная проверка не считается сетевой приёмкой.
