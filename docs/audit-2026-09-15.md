## Карта и границы проверки

```text
main → make_demo_game → run_application → Application
Application: delegate + SDL + config + Window + Renderer + AudioSystem
Window: SDL window + GL context
EngineServices: заимствованный доступ к подсистемам
DemoGame: GameWorldRuntime + WorldSceneRenderer + runtime snapshot
TOML → BlockoutLoader → validation → LevelSessionBuilder → runtime/scene
events → update → fixed simulation → prepared render queue
→ shadow/main passes → ImGui → swap
AppShutdownGuard → game resources shutdown → renderer → window/context → SDL
```

Проверены bootstrap, порядок владения и shutdown, frame/input policy, загрузка config/уровней, трансформации модулей, основные renderer/resource paths, audio lifecycle, регистрация tests, presets и CI. Исходники открывались по связанным путям; это не построчный разбор всех файлов.

Наблюдения без оснований для переписывания:

- Simulation имеет шаг 1/120 и максимум 8 шагов; FrameTimer ограничивает длинный delta. Непоказываемое окно использует event wait, quit прекращает frame.
- Gameplay input учитывает захват ImGui, relative mouse mode и потерю фокуса.
- Shader/program и shadow resources уже имеют RAII; reload подготавливает renderer/world state. Полная транзакционность ошибок после commit не гарантирована и уже оговорена в architecture document.
- Asset root по умолчанию расположен рядом с executable. Smoke из другого рабочего каталога подтвердил этот путь.
- Color pipeline по умолчанию остаётся `legacy_gamma`. Behavioral sRGB readback выполняется при инициализации, а не каждый frame. Scene/shadow/ImGui state boundaries сохранены.
- Overlay authoring data model пока не выбирается runtime: текущая документация честно описывает эту незавершённую интеграцию.
- Все найденные test `.cpp` зарегистрированы в CMake. Unit/content/graphics — разные группы CTest; обычные workflows не запускают графические тесты.

## Исправленные findings

### RC-MEM-001 — утечка ресурсов при исключении в конструкторе Window

- Severity: High. Confidence: High. Priority: P0. Status: исправлено.
- Location: `src/relaycore/platform/window.cpp`, `Window::Window`.
- Evidence: новый `graphics.window_lifetime` на исходном коде завершился ошибкой: `windows=1, current_context=0000000000010001` после исключения logger.
- Current behavior до исправления: handles уже сохранены, но последующие SDL attribute queries или logging могут бросить исключение; деструктор недостроенного Window не вызывается.
- Impact: SDL window и GL context остаются живыми на failed startup path.
- Trigger: исключение после успешного создания контекста. Тест вызывает реальную ошибку неинициализированного logger в конце конструктора.
- Recommendation / Minimal safe fix: локальные `unique_ptr` с SDL deleters до последней бросающей операции, затем `release` в поля владельца. Удалены ручные ветки cleanup, которые также могли затереть исходный SDL error до создания исключения.
- Verification: тест сначала FAIL, затем PASS для обоих pipeline modes; повторный PASS под ASan. Штатные startup/render/shutdown smoke обоих modes — exit 0.
- Scope: S. Regression risk: Low.

### RC-COR-001 — loader принимает нечисловые результаты и переполнение float

- Severity: High. Confidence: High. Priority: P1. Status: исправлено.
- Location: `src/relaycore/world/blockout_loader_parse.cpp`, `parse_vec3`, `parse_optional_float_field`.
- Evidence: два новых публичных loader tests приняли все пять недопустимых значений: `nan`, `inf`, `-inf`, `1e100`, `-1e100`.
- Current behavior до исправления: TOML double без проверки преобразуется в runtime float; проверки положительности не отсекают NaN.
- Impact: некорректные координаты/визуальные значения доходят до runtime, geometry и GPU paths.
- Trigger: недопустимое число в typed vector/scalar полях уровня, например `solid.mins` или `solid.brightness`.
- Recommendation / Minimal safe fix: проверять конечность и представимость в float до преобразования, выдавая исходный dotted field name.
- Verification: оба tests сначала FAIL, затем PASS; 199 unit + 9 shipped-content tests прошли в Debug, RelWithDebInfo и ASan.
- Scope: S. Regression risk: Low. Корректные authored values не менялись.

### RC-COR-002 — поворот module instance изменяет pitch spawn

- Severity: Medium. Confidence: High. Priority: P1. Status: исправлено.
- Location: `src/relaycore/world/blockout_loader_transform.cpp`, `rotate_module_entity`; direct consumer — `LevelSessionBuilder`.
- Evidence: regression test с authored angles `[180, 15, 0]` показывает неверные yaw и pitch при ненулевых quarter turns.
- Current behavior до исправления: rotation прибавлялась к `angles.y`; spawn трактует данные как `[yaw, pitch, roll]`.
- Impact: игрок появляется с неверным горизонтальным направлением и наклоном камеры в повёрнутом модуле.
- Trigger: module instance с authored spawn angles и `rotation_y`.
- Recommendation / Minimal safe fix: прибавлять rotation к первому компоненту, сохраняя pitch/roll.
- Verification: публичный `LevelSessionBuilder` test сначала FAIL, затем PASS для 0, 90, 180, 270, -90 и 450 градусов; все три конфигурации прошли regression suite.
- Scope: XS. Regression risk: Low.

### RC-BUILD-001 — локальный CMake cache смешивает MSVC и MinGW

- Severity: High. Confidence: High. Priority: P0. Status: локально устранено, без изменения presets.
- Location: исходные `build/msvc-debug/CMakeCache.txt`, `build/msvc-relwithdebinfo/CMakeCache.txt`.
- Evidence: configure запускал MinGW `ld.exe` с аргументом MSVC `/machine:x64` и завершался `unrecognised emulation mode: achine:x64`; в cache также находился чужой `ar.exe`.
- Current behavior до исправления: даже compiler probe не собирался.
- Impact / Trigger: documented MSVC workflow не работает с этим старым cache.
- Recommendation / Minimal safe fix: обоснованный `cmake --fresh --preset ...` в VS developer environment; build directories и пользовательские presets не удалялись.
- Verification: Debug и RelWithDebInfo workflows затем прошли. После переустановки зависимостей один configure сообщил об отсутствующих package files; проверка наличия файлов и повторный configure устранили этот промежуточный сбой без правок исходников зависимостей.
- Scope: XS. Regression risk: Low. Нет tracked build-system patch для этой внешней причины.

### RC-DOC-001 — неверное описание владельца DemoGame

- Severity: Low. Confidence: High. Priority: P3. Status: исправлено.
- Location: `docs/ARCHITECTURE.md`, Bootstrap/Ownership.
- Evidence: `make_demo_game` возвращает `unique_ptr<AppDelegate>`, который передаётся в `Application::app_delegate_`; документация описывала локальный объект в main и borrowed delegate.
- Current behavior: код владеет delegate через Application и использует shutdown guard.
- Impact / Trigger: неверная модель lifetime при дальнейшем обслуживании startup/shutdown.
- Recommendation / Minimal safe fix: исправить bootstrap map, owner table и описание shutdown guard.
- Verification: сопоставление с `main`, `run_application`, `Application`; `git diff --check`.
- Scope: XS. Regression risk: Low.

## Performance и оставшаяся работа

### RC-PERF-001 — временные списки в WorldSceneRenderer

- Severity: Low. Confidence: High для существования allocation, не установлена для влияния на frame time. Priority: P3. Status: не исправлялось.
- Location / Hot path: `src/relaygame/world_scene_renderer.cpp:507`, `:560`, `WorldSceneRenderer::render`.
- Evidence / Current behavior: локальные `transparent_chunks` и `sorted_lights` создаются и reserve-ятся заново при render.
- Frequency / Cost model: каждый отображаемый frame; до двух временных allocations, O(chunks + lights) ёмкости и O(lights log lights) сортировка.
- Impact: влияние на FPS не измерено; это кандидат для профилирования, а не доказанный bottleneck.
- Trigger: загруженная сцена с render chunks и локальными источниками.
- Recommendation / способ измерения: Tracy capture одинакового camera path в `test_room`/`stress_room_02`, отдельно allocation count и CPU frame time при одинаковом VSync.
- Minimal safe fix при подтверждённой значимости: переиспользовать scratch vectors существующего владельца; новый manager/cache layer не требуется.
- Verification: только source inspection; before/after measurements отсутствуют.
- Scope: S. Regression risk: Low.

Изменений производительности и заявлений о приросте FPS нет. Startup framebuffer readback сохранён как проверка correctness.

Ограничения проверки:

- Smoke короткий: продолжительный playthrough, ручной visual review, интерактивный F7 reload и GPU/SDL attribute failure injection не выполнялись. Content acceptance tests проверяют штатные gameplay/snapshot сценарии.
- Новый lifetime test воспроизводит позднее исключение logger; отдельные SDL/backend отказы не инжектируются.
- Проверка typed float parsing не является полной валидацией всех строковых entity properties или пределом размера мира. Экстремальные конечные координаты и арифметика последующих transforms требуют отдельного boundary/fuzz audit.
- ASan не доказывает отсутствие всех видов UB. Release отдельно не собирался; оптимизированная проверка выполнена через RelWithDebInfo.
- Authoring overlay runtime selection и encoded-space ImGui composition остаются ранее задокументированными ограничениями.
