# H-008 — локальный baseline после G-016, 2026-10-08

По поручению «сначала коммит, затем дальше по плану» текущие G-016/G-017
зафиксированы коммитом `fc88baa`. Следующий D5 начат с доступной локальной
части H-008. Независимый игрок и другой ПК ранее отложены; этот захват их
не заменяет. Полный H-008 не завершён.

## Условия и границы

Windows, RTX 4060 Ti 8188 MiB, драйвер 596.49, GPU API 1.4.329 при требовании
Vulkan 1.3. Preset `msvc-relwithdebinfo`, Tracy client/capture/export 0.14.1,
1280×720, VSync off, hardware sRGB, HDR on, shadows on, audio off,
runtime validation=false. При захвате сборки и другие GPU tests не выполнялись.
OS/driver caches не очищались: первый запуск процесса не означает cold cache.

`relaycore_bench_relay_run --pressure-transfer --profile` сначала проверяет
два CPU-маршрута, затем запускает обычные update/render/UI/present над
изолированными disk saves: entry/distance/cover/powered, два повтора по 2 с.
Это восемь подготовленных состояний, а не непрерывное движение игрока или
измерение длительности эпизода. Пользовательский progress не изменялся.

Tracy содержит 12 421 `BenchRelay::frame`; frame zones включают обвязку runner.
В таблице warm исключает только первый кадр каждого состояния. GPU statistics
включают все GPU zones внутри состояния; loading измерен от начала state zone
до первого frame и включает создание изолированного save и подготовку сессии.
Runner отдельно пишет update/render/UI/present wall times в run log.

Затраты подготовки остались в loading; сокращение общего времени загрузки
не заявляется.

`DemoGame::on_update` p99 — 0,063–0,099 мс. Runner present p99 —
0,455–0,510 мс. CPU render/UI включает scene fences: эти вложенные интервалы
и GPU execution нельзя складывать как независимые затраты. В выбранных
состояниях заметный CPU вклад связан с render/UI и ожиданием scene completion;
это описание измерений, а не доказательство причины задержек полного маршрута.

Только внутри восьми state intervals: `PhysicsWorld::cast_box` p99 на вызов —
0,00443–0,00590 мс, 720–1560 вызовов на состояние; `PhysicsWorld::raycast`
p99 — 0,00485–0,00582 мс, по 480 вызовов в entry/distance/cover каждого повтора.
В powered raycast zones отсутствуют. CPU-маршруты до rendered states в эти
числа не входят. Распределения полных вызовов не являются суммарной query cost
кадра; вложенные wrapper/backend zones отдельно не суммировались.

Новая карта после G-016 имеет другой состав сцены относительно E-018:
draw/triangle counts и layout изменены. Поэтому прямое before/after сравнение
как доказательство ускорения не выполнялось. Основания для performance patch
по этим состояниям не установлены; runtime и настройки не менялись.
