# G-012 — optimized first-use / warm, 2026-10-07

Локальный baseline `bench_relay`, без оптимизаций и claims о speedup. Проверен новый короткий workload; H-008 полного `pressure_transfer`, человеческий маршрут и другой GPU остаются открытыми.

Capture сделан до параллельного обновления GLB/exporter/model manifest в общем checkout. Эти последующие asset edits в G-012 commit не входят; новый `lab_bench.glb` остановил повторную сборку на degenerate triangle, а изменяемый manifest затем ссылался на отсутствующий `scientist_hazmat.glb`. Данные ниже относятся к записанным бинарникам/staged assets и прежним моделям `2440823`; переносить цифры на новые модели без повторной проверки нельзя.

## Сборка и воспроизведение

- `dev`, рабочее дерево G-012 поверх `2440823`, затем checkpoint commit с этим отчётом. Windows 11 Pro `10.0.26200`, Ryzen 7 3700X, 32 GiB RAM; RTX 4060 Ti 8 GiB, NVIDIA `596.49`, Vulkan device API `1.4.329`.
- Presets `msvc-relwithdebinfo` / `demo-relwithdebinfo`, MSVC `14.51.36231`, Tracy `0.14.1` включён. Runtime log подтверждает **validation=false**; Debug smoke отдельно выполняется с validation=true.
- 1280×720, high DPI off, VSync off, hardware_srgb, HDR on, ImGui/HUD on, audio off, shadows on, shadow map 1536. Остальные значения — staged `assets/config/engine.toml` и `render_authoring.toml` checkpoint. Настройки renderer не изменены ради результата.
- `relaycore_bench_relay_run --profile` создаёт entry, encounter и powered saves из полного scripted маршрута. Затем новый DemoGame восстанавливает каждое состояние с диска, выполняет настоящие update/render/UI/present две секунды и возвращается в меню. Последовательность повторяется в том же renderer. Камера стационарна; в encounter rover продолжает движение, удерживаемой стрельбы и человеческого ввода нет.
- Первый проход означает first-use в новом процессе/renderer. OS file cache и driver shader cache не очищались. Warm означает повторную загрузку этих же состояний, а не сохранение всех GPU meshes живыми между сессиями. Это capture трёх повторяемых состояний; полный scripted маршрут в начале проверяет CPU gameplay, но непрерывный rendered проход игрока не измерялся.

Новый `Vulkan scene fence` измеряет только vkWaitForFences; две зоны на кадр суммированы. Upload CPU и upload wait — отдельные интервалы CPU, не измерение GPU transfer duration: первый включает preparation/driver submit work, второй учитывает завершение передачи. GPU durations нельзя прибавлять к ним как независимые затраты. В каждой двухсекундной сессии uploads сосредоточены в первом кадре, последующие кадры их не имеют. First entry: 118 mesh и 21 texture uploads; warm entry: 56 mesh uploads без texture upload. Повторные mesh uploads соответствуют новой игровой сессии и lifetime ресурсов, а не доказанной регрессии.

Подтверждено: native queries малы в этом workload; scene fence занимает заметную часть CPU wall frame. Spike 46,88 мс совпал с первым render и массовыми uploads; GPU Scene frame max там 0,4393 мс, scene fence sum max 1,2126 мс. Capture не отделяет compilation всех Vulkan pipelines от остального first-use preparation, поэтому весь spike не приписывается одной причине. Это один короткий запуск на одном ПК, без заданного целевого FPS/слабого ПК; continuous movement/fire и человеческая длительность требуют отдельного прохода. Renderer architecture и ресурсные кеши в этом checkpoint не оптимизировались.
