# E-018 — подготовка GPU-ресурсов сессии, 2026-10-07

Consumer: вход и повторные сессии `pressure_transfer` после G-015. Это локальный first-use workload; непрерывный человеческий проход H-008 и другой ПК остаются отдельной приёмкой.

## Реализация и границы

`WorldSceneRenderer::resource_items()` перечисляет CPU mesh/material pairs для всех chunks, native/OBJ props, противников и их уничтоженных вариантов, дверей, usables, viewmodel, FX и inspector. Перечень не зависит от текущей visibility или состояния устройства. `Renderer`/подготавливаемый backend выполняет acquisition и upload waits до установки игровой/editor-сессии либо commit reload/HDR backend. Vulkan ownership, synchronization и lazy acquisition для прочих render consumers сохранены.

Промежуточный capture `e018-after.tracy` выявил ещё 19 texture uploads в первом кадре: shadow-caster submissions не несут normal/factors основного material, а общий `prepare(shadow_casters)` создавал ненужные material variants. `draw_shadow` использует только mesh buffers; финальный backend подготавливает для opaque shadows только геометрию. Regression намеренно подаёт casters без normal/factors и проверяет отсутствие новых allocations и прежние pixels.

Перед acquisition renderer ждёт свой текущий frame и удаляет resources с expired CPU identities; upload staging освобождается после завершения. Подготовка новой сессии не уничтожает CPU resources активной сцены. При неудаче подготовленная сцена отбрасывается; следующий prepare/render очищает её expired GPU entries. Нового residency/catalog/cache framework и изменения steady-state scheduling нет.

## Сопоставимый workload

Рабочее дерево поверх `c1118a1`, включая G-015, затем E-018. Before снят после последних mounting fixes и G-015, до изменения GPU preparation. Preset `msvc-relwithdebinfo`, Tracy 0.14.1; Windows 11, RTX 4060 Ti 8 GiB, driver 596.49 (проверен `nvidia-smi`), runtime GPU API 1.4.329 при требовании 1.3, validation=false. Это тот же локальный ПК, что в [G-014](G-014-2026-10-07.md).

`relaycore_bench_relay_run --pressure-transfer --profile`: два scripted CPU-маршрута, затем entry/distance/cover/powered disk saves в настоящем DemoGame, по две секунды update/render/UI/present, два прохода в одном renderer. 1280×720, high DPI/VSync/audio off, hardware_srgb, HDR/ImGui/shadows on. First-use — новый процесс/renderer; OS/driver caches не очищались. При capture не выполнялись другие builds/GPU tests. Loading включает `on_startup` и `begin_episode`; он может подготовить более одной сцены, поэтому не равен одному вызову resource preparation.

Before: `build/msvc-relwithdebinfo/e018-before.tracy`, log `tests/e018-before-run.log`, 14 161 CPU frame zones. Первый игровой кадр — 122,943 мс; следующие session first frames — 15,444–19,060 мс. В первом кадре каждого состояния есть 110–227 mesh/texture uploads и столько же waits. Before identity: `build/msvc-relwithdebinfo/e018-before-identity.json`.

Финальный after: `e018-final.tracy`, log `tests/e018-final-run.log`, 14 372 CPU frame zones; workload passed. Во всех восьми состояниях нет mesh/texture uploads и upload waits ни в первом, ни в последующих игровых кадрах. Draw counts и triangles совпадают с before: 85 draws для entry/distance/cover, 77 для powered; 39 418 / 39 418 / 40 404 / 41 190 triangles соответственно.

Warm CPU frame p99 (без frame 0) по состояниям: before 1,608–2,038 мс, after 1,583–2,435 мс. GPU `Scene frame` p99: before 0,250–0,300 мс, after 0,247–0,300 мс; CPU scene-fence p99: 0,683–1,109 / 0,831–1,087 мс. Steady-state speedup не заявляется. Первый after frame всё ещё включает target/UI/present first-use и 3,528 мс scene fences; устранён конкретный mesh/material upload path.

Цена: loading вырос, поскольку до игры готовится полный набор ресурсов, включая offscreen chunks и неактивные варианты; runner подготавливает две сцены в loading каждого state. Это перенос затрат и расширение подготовки, а не обещание сокращения total load time. В resource fixture (640×360, SDR, default shadows) VMA allocation bytes после первого lazy render — 118 491 488; после подготовки полного набора — 123 730 688 (+5 239 200 bytes, 4,996 MiB). Три повторения дают ровно 323 allocations / 123 730 688 bytes в Debug и optimized. При следующих lazy renders часть shared model resources уже resident; промежуточно 123 354 928 bytes. Это фактическая стоимость fixture, включая backend/targets, не peak VRAM/RSS всей игры. Evidence: `e018-final-resource-memory.txt` в обоих build trees.

## Проверки и отдельный baseline failure

`graphics.resource_preparation` сравнивает pixels до/после подготовки ресурсов, проверяет отсутствие дополнительных VMA allocations при rendering подготовленной scene/viewmodel, стабильные allocation count/bytes в трёх повторениях и cleanup/сохранность активного изображения после частично неудачной подготовки. Gameplay/lifecycle/HDR проверки используют обычные session/menu/editor/reload/transition flows; технические routes не заменяют отложенную человеческую приёмку G-015.

Debug: 36/36 targeted mission/session/save/pressure tests и graphics resource/lifecycle/bench/pressure/HDR-settings/power-restoration прошли без failures/skips (`e018-final-debug.xml`). После последней shadow-material правки заново пройдены 6/6 affected graphics, включая point-shadow receiver (`e018-shadow-debug.xml`). Optimized финального дерева: 14/14 pressure content и тех же шести graphics без failures/skips (`e018-final-optimized.xml`). Check Map `valid=true`, warnings=[] (`build/msvc-debug/g015-map.json`). Просмотрены Debug entry/cover BMP; exact pixel comparison после preparation и failed prepare выполняется в GPU regression. Обычная optimized игра обновлена; исходная карта и обе staged копии имеют одинаковый SHA-256. `clang-format --dry-run --Werror` 21 изменённого C++ файла и `git diff --check` прошли.

Дополнительно запущенный общий `graphics.vulkan_mesh` падает на старом `mesh-reload-0`: `mask_diff=0`, `color_diff=0.111389`, `mean_rgb_delta=3.32784`, до вызова нового resource test. Для causal check временно собран `vulkan_mesh_renderer.cpp` из `HEAD` с теми же текущими assets; E-018 API в probe бросал исключение при любом вызове. Получено то же расхождение с теми же числами, без вызова E-018 API. Рабочий патч затем восстановлен и пересобран. Evidence: `build/msvc-debug/e018-debug.xml`, `e018-original-backend.xml`, `e018-original-backend-ctest.log`. Старые `.rcgb` не обновлялись; это отдельное существовавшее расхождение render baseline, а не зелёный полный graphics suite.

## Воспроизведение

В VS developer environment с `VCPKG_ROOT`, соответствующим существующему cache:

```powershell
cmake --build --preset validation-relwithdebinfo --target relaycore_demo relaycore_bench_relay_run relaycore_content_validation relaycore_game_lifecycle relaycore_vulkan_mesh_tests -j 2
# Отдельный процесс до workload:
build/profiling/tracy-0.14.1/tracy-capture.exe -o build/msvc-relwithdebinfo/e018-final.tracy -s 25
# Рабочая папка build/msvc-relwithdebinfo/tests:
$env:RELAYCORE_ASSET_ROOT = 'E:/Code/C++/RelayCore/build/msvc-relwithdebinfo/src/relaygame/assets'
./relaycore_bench_relay_run.exe --pressure-transfer --profile
```

CPU CSV: `tracy-csvexport -u -f 'BenchRelay::'` и `-u -f 'Vulkan '`; GPU CSV: `-g`. Скрипт сопоставления CPU frame/state/loading intervals — `build/msvc-relwithdebinfo/e018_analyze.py`; результаты `e018-{before,final}-analysis.json`. CSV CPU rows с запятыми разбираются справа по шести полям. Nested CPU/GPU zones не складываются как независимые затраты.

Final checks:

```powershell
ctest --test-dir build/msvc-debug -R 'mission|respawn|retry|^validation\.pressure transfer|^relaycore\.level session|^relaycore\.saved game|^relaycore\.runtime level snapshot|^graphics\.(resource_preparation|game_lifecycle|pressure_transfer|bench_relay|power_restoration|hdr_settings)$' --output-on-failure --no-tests=error --output-junit e018-final-debug.xml
ctest --test-dir build/msvc-debug -R '^graphics\.(resource_preparation|point_shadow_receiver|game_lifecycle|hdr_settings|pressure_transfer|bench_relay)$' --output-on-failure --no-tests=error --output-junit e018-shadow-debug.xml
ctest --test-dir build/msvc-relwithdebinfo -R '^validation\.pressure transfer|^graphics\.(resource_preparation|point_shadow_receiver|game_lifecycle|hdr_settings|pressure_transfer|bench_relay)$' --output-on-failure --no-tests=error --output-junit e018-final-optimized.xml
```
