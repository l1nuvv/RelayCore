# G-017 / D4 — Контур охлаждения, 2026-10-08

Автор явно выбрал отложить приёмку G-016 и начать новый компактный эпизод D4.
Техническая часть выполнена; статус и дальнейший порядок принадлежат
[roadmap](../tickets/G-017.md#g-017--d4--контур-охлаждения-и-повторяемое-производство).
Это не независимый человеческий playtest. G-016 и внешние критерии остаются открытыми.

## Результат

В меню новой игры появился **«Контур охлаждения»** (`levels/cooling_loop.toml`).
Центральный агрегат разделяет сервисный проход с ближним rover и открытую линию
под турелью. Можно выбрать подход и оружие; дробовик доступен у входа, но не обязателен.
Остекление пускового поста позволяет видеть оборудование до снятия блокировки.
Изоляция утечки прекращает пар/аварийный свет и открывает перегородку.
Пуск меняет освещение, включает два вентилятора и рабочий ambient,
разблокирует пульт выхода. Четыре этапа миссии завершаются отдельным финалом.
После изоляции смерть возвращает к сервисному пульту без отката мира.

Использованы семь существующих native model families: transfer_cover_casing,
pressure_control_casing, pressure_manifold, utility_pipe, ventilation_unit,
fluorescent_fixture, safety_notice. Оболочка и collision volumes собраны в TOML;
native products, receipts и manifests компилятора вручную не исправлялись.
Новые runtime rules, dependencies, GLB exports и irradiance products не потребовались.
Повторно использованы mission/interaction/doors, rover, weapons, save/retry,
environment/audio zones и editor serialization.

Изменённые пути: новая карта; `demo_game_menu.cpp`/`demo_game_progress.cpp` для
выбора и финала; `tests/cooling_loop_{route.h,tests.cpp}`, CMake registration
и режим `--cooling-loop` существующего `bench_relay_run.cpp`.
По показанному автором build warning в `save_game.cpp` локально переименован
набор enemy IDs: C4456 исчез при последующей optimized unity compilation.

## Проверки

Все build-команды выполнялись в VS developer environment с
`VCPKG_ROOT=C:/Program Files/Microsoft Visual Studio/18/Community/VC/vcpkg`.

```powershell
cmake --build --preset validation-debug --target relaycore_content_validation relaycore_bench_relay_run relaycore_demo relaycore_tests relaycore_level_check
ctest --preset validation-debug -R '^validation\.cooling loop' --no-tests=error --output-on-failure --output-junit D4-content.xml
ctest --preset test-debug -R '^relaycore\.(saved game|campaign save|invalid save|malformed and unsupported saves|save compatibility)' --no-tests=error --output-on-failure --output-junit D4-saves.xml
ctest --preset graphics-debug -R '^graphics\.(cooling_loop|bench_relay|pressure_transfer)$' --no-tests=error --output-on-failure --output-junit D4-graphics.xml
cmake --build --preset validation-relwithdebinfo --target relaycore_demo relaycore_content_validation
ctest --preset validation-relwithdebinfo -R '^validation\.cooling loop' --no-tests=error --output-on-failure --output-junit D4-content-optimized.xml
ctest --preset graphics-debug -R '^graphics\.cooling_loop$' --no-tests=error --output-on-failure --output-junit D4-final-graphics.xml
git -c core.safecrlf=false diff --check
```

Debug content **4/4**, optimized content **4/4**, save tests **5/5**.
Затронутый общий graphics harness **3/3**, после финального добавления обзорного
окна снова content **4/4** на обеих конфигурациях и cooling graphics **1/1**.
Graphics действительно выполнены, failures/skips и срабатываний validation gate нет.
Обе тактики прошли через реальные collision queries и focus/use до финала без смертей;
service использовала дробовик, firing — только точное оружие, с большим числом
ticks открытой линии турели. Это доказывает техническую достижимость, не баланс.
Проверены отрицательные gates, коллизия остекления, disk continue до/после запуска,
encounter restore, death/local retry, editor round trip с сохранением fingerprint,
steam/fan/light state и выбор audio zone.

CLI `build/msvc-debug/src/relaygame/relaycore_level_check.exe assets/levels/cooling_loop.toml`
с `RELAYCORE_ASSET_ROOT=build/msvc-debug/src/relaygame/assets` дал `valid=true`, warnings=[];
вывод — `build/D4-map-check.json`. Scoped clang-format и diff-check прошли.
JUnit лежат в соответствующих `build/msvc-{debug,relwithdebinfo}`.

Свежие 1280×720 HDR/hardware_srgb/VSync off captures просмотрены:
`build/msvc-debug/tests/cooling-loop-captures/{entry,service,standby,powered}.bmp`.
Standby/powered имеют одинаковую камеру; после первого просмотра усилено изменение
света и добавлен вентилятор прямо над пультом. Звук capture harness отключён;
реального прослушивания не было. Full suite, ASan и Tracy-профиль не запускались.

## Production loop и затраты

| Операция | Факт / затраты |
| --- | --- |
| Placement | Одна новая TOML-карта; семь reused model families; вручную заданы помещения, два пути, опора турели, 01/02/03 и связи устройств. Отдельный таймер активной работы автора не вёлся |
| Export / compile | Новых exports нет; существующие models/collision проходят штатные зависимости сборки. Probe steps подтвердили reuse 48/30/18 продуктов прежних сцен |
| Первый Debug build/check targets | 25,65 с Stopwatch, включая configure после добавления test source и staging; не clean build |
| Следующая сборка content/capture/demo | 12,26 с Stopwatch, с новым capture mode; это другой workload, не before/after speedup |
| Финальная optimized сборка | 45,88 с Stopwatch после закрытия работающей игры; runtime/content unity compilation и linking/staging |
| Повтор unchanged staging | `cmake --build --preset validation-debug --target relaycore_demo_assets`: 0,64 с Stopwatch |
| Reload/preview | Изолированные disk continue для четырёх состояний, два прохода harness; финальный graphics check 4,72 с CTest, не player duration и не performance baseline |
| Исправления | Уточнён тестовый обход стола с оружием; ожидания mission status приведены к существующему 1-based API; учтено плавное затухание effects; после просмотра усилена реакция света; добавлено обзорное окно |
| Блокеры среды | Первый sandbox build не получил штатный MSVC/vcpkg; выполнен в полном developer environment. Sandbox temp rename мешал save test; нормальный запуск прошёл. Optimized DLL были заняты запущенной игрой — автор закрыл её, повторная сборка успешна |

Этот cycle подтвердил reuse без копирования gameplay logic и ручного ремонта products.
Повторяемый дефект editor/pipeline с измеренным before/after не установлен;
новый tooling framework или speculative optimization не добавлялись.
В следующем content cycle полезно отдельно замерить активное placement/link authoring:
нынешние build/stage times не измеряют эту ручную стоимость.

## Brief игроку и открытая приёмка

Дать игроку только этот абзац: выберите **«Контур охлаждения» → «Начать прохождение»**.
Восстановите контур и покиньте сектор. WASD/мышь — движение и обзор, E — действие,
ЛКМ — огонь, 1/2 — оружие, F — фонарь. Пройдите самостоятельно, затем расскажите,
где было непонятно, почему выбрали путь и оружие и что изменилось после действий.
Новая игра заменяет прежний progress через обычное подтверждение игры.

Наблюдателю отдельно записать время, смерти, вмешательства, выбор пути/оружия,
понимание аварийной перегородки/пуска/выхода, замеченный свет и вентиляцию.
На повторе проверить continue и retry; прослушать standby/running.
Длительность, удовольствие, понятность и авторская приёмка пока не установлены.
