## Contract and budgets

All effects default off. Bloom and SSR require the existing scene-linear FP16
HDR path; the output is still SDR. Their menu controls select HDR when enabled,
and selecting SDR turns them off. SSAO and volumetrics also support SDR.
No temporal accumulation, jitter, new dependency or queue is introduced.

Explicit frame dependencies:

1. Existing shadows and optional single-sample depth/mapped-normal inputs.
2. Optional 12-sample SSAO, consumed with a 3×3 depth/normal-aware filter.
   The minimum of authored AO and screen AO affects indirect light only.
3. SSR alone renders opaque source radiance with probe reflections, copies it
   into a sampled target, then renders the final scene. Forty bounded projected
   depth steps and five hit refinements blend screen radiance with the existing
   environment/probe contribution before the material BRDF. Edge, thickness,
   normal-facing, distance and roughness rejection retain probes on misses.
   Roughness ≥0.65 uses probes. This bounded first implementation uses direct
   depth tracing rather than a Hi-Z hierarchy and costs an extra opaque pass.
4. Homogeneous single-scattering volumetrics integrate eight midpoint samples over
   at most 24 world units, with directional/local/spot light shadow visibility
   and exponential transmittance. They replace distance fog on opaque surfaces;
   transparent/overlay/viewmodel shading retains the existing fog policy.
   Fog alone compiles without screen-input samplers and allocates no geometry or
   history targets. SSR source radiance excludes camera-to-hit fog, avoiding a
   second atmospheric integration when shading the receiver.
5. World/transparents/viewmodel → optional bloom bright extraction at half
   resolution → four FP16 reduction levels → weighted linear upsampling in
   tone mapping → display-space RmlUi and developer ImGui.

AO/SSR exclude transparent, overlay, background and first-person weapon input
coverage. Bloom can include bright viewmodel/transparent emission; UI never
enters it. Spatial effects use current-frame geometry and need no dynamic-object
history. Existing 06c history diagnostics retain their separate reset contract.
Both scene slots own effect images, descriptors and final-use completion;
shader reload stages the complete working pipeline set before replacement.

Authored controls in `[render]`: `bloom_enabled`, `bloom_strength` [0,1],
`bloom_threshold` [0,10] scene-linear units, `ssao_enabled`, `ssr_enabled`,
`volumetrics_enabled`, `volumetric_density` [0,0.1]. Invalid data fails explicitly.
Saved player switches live in the existing settings file. Optional unsupported
FP16 bloom filtering/blits or input formats fail only the requested effect.

`RELAYCORE_VULKAN_PASS_INPUT_VIEW` also accepts `ao`,
`reflection_confidence` and `volume_transmittance`; the corresponding effect
must be enabled. These views retain ordinary display mapping/UI composition.

Budgets selected before measurement: optimized 1920×1080, RTX 4060 Ti, VSync off,
hardware sRGB/internal HDR. Warm GPU p99: bloom <1 ms; SSAO <1.5 ms; additional
SSR source/final work <5 ms; volumetric overhead <4 ms; combined scene <16.67 ms.
Record effects individually against the same off fixture; compare complete
frame distributions and memory separately. GPU intervals are nested, so their
sum is not a frame cost. These are local acceptance budgets, not other-GPU claims.
