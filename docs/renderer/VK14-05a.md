# VK14-05a — persistent material descriptor pooling

Selected by the owner's “дальше по плану” request on 2026-10-12, after the
VK14-00–04 local gates and required Vulkan 1.4 revision. This task covers material
descriptor pooling only; pipeline caching, format selection, surface loss and
memory telemetry remain separate VK14-05 tasks.

## Scope and implementation

Baseline source: `f217e9a500bc243873d5c1d29ba1adc87a5acf8f`. Each mesh material
previously created one Vulkan descriptor pool containing two sets, one for each
scene slot. The same seven UBO and ten combined image-sampler bindings per set
remain in use, with no shader/layout/asset changes.

`VulkanMeshRenderer::State` now owns blocks of 128 materials (256 sets) with
individual set freeing. Material allocations reuse available blocks before
growing; out-of-pool/fragmentation results try another block, while other Vulkan
errors fail explicitly. A material releases its two sets only when its existing
scene and upload completion conditions allow destruction. Stable block addresses
outlive their active and retired materials. Collection deletes empty extra blocks
and keeps at most one empty block for reuse; backend shutdown drains GPU work and
destroys all blocks. No transient frame allocator or bindless path is introduced.

The renderer exposes pool/material counts, including retired materials, for
the GPU fixture. Runtime ownership is documented in
[ARCHITECTURE](../ARCHITECTURE.md#graphics-backend-direction).

## Fixture and acceptance

`graphics.material_descriptors` uses a 192×192 linear/SDR target, disabled shadows,
one retained material and 1,025 distinct 1×1 textured materials on a grid. It runs
three cycles of allocation, freeing alternate materials, refilling, rendering,
GPU-blocked retirement and complete reclamation. Its budget is at most 16 pools
for 1,026 simultaneously owned materials, no growth when refilling freed slots,
and one pool/one material after collection. VMA allocation count returns to the
settled baseline. Successful/failed shader reload, failed preparation and pixel
identity after reuse are also checked.

The host-signaled queue gate prevents actual scene completion while source
textures expire, making early descriptor/pool reclamation observable. Conventional
descriptor sets, the existing two-slot bindings and existing graphics pipeline
remain the baseline path. This task adds no optional feature or graphics setting.
Pool-count reduction is the acceptance measure; no frame-time speedup is claimed.

Affected files: `src/relaycore/render/vulkan_mesh_renderer.{h,cpp}`,
`tests/vulkan_mesh_tests.cpp`, `tests/CMakeLists.txt`, the runtime ownership document
and the owning renderer plan/report.
