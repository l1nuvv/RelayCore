# VK14-10a/b — CPU instancing and indirect submission

Executed 2026-10-13 from source base `d3bdf6e0d0421ef51467802daf6c3385a154132f`.
10a is implemented with a passing local parity/stress gate. 10b is implemented
and parity-checked as an opt-in path; it does not earn an additional default CPU
performance win. 10c GPU culling was not selected.

## Scope and contract

The implementation stays inside `VulkanMeshRenderer`, its offline Slang shaders
and the existing mesh fixture. It merges adjacent compatible opaque mesh/material
items, preserving submitted order even for equal-depth surfaces. Shadow grouping
follows the existing caster/range/frustum filters. Transparent, overlay and
viewmodel draws remain individually ordered. CPU world culling and inspector
picking retain their owners; original temporal correspondence crosses batching
explicitly. Single-object draws use the existing push-constant transform path.
Passes without adjacent geometry bypass CPU instance staging.

Two scene slots own mapped instance/indirect buffers and wait for final GPU use
before reuse/growth. The shared record is 128 bytes with checked host offsets;
limits, byte ranges and command counts are checked. CPU writes are flushed before
submission. Indirect submission uses one `VkDrawIndexedIndirectCommand` per
compatible batch, zero `firstInstance`, and a push-constant storage offset. It
requires neither multi-draw nor indirect-first-instance features. Geometry
packing, bindless and GPU command generation are outside this patch. Runtime
controls are owned by [RENDERING](../RENDERING.md#scene-submission--vk14-10ab).
The [Vulkan indirect-draw contract](https://docs.vulkan.org/refpages/latest/refpages/source/vkCmdDrawIndexedIndirect.html)
provides the command/feature constraints.

## Performance

RTX 4060 Ti; loader/headers 1.4.357, GPU API 1.4.329, raw driver `2500608000`.
Optimized `msvc-dev` has Tracy 0.14.1 and validation disabled. Workloads run
sequentially without overlapping builds/GPU checks. Driver/OS caches are warm;
these are not cold-installation, full gameplay or hardware-wide FPS claims.

`--scene-submission-profile`: 4,096 repeated boxes, 640x360, hardware-sRGB,
SDR, MSAA 1, shadows/fog/post noise off, no audio/UI/presentation. Each mode has
280 submitted frames, 40 warm-up and 240 measured samples, paced by an excluded
8 ms SDL delay. CPU recording is the sum of nested scene draw-recording scopes
inside each CPU frame; GPU scene time comes from Tracy timestamps. Do not add
CPU/GPU or nested scopes as independent frame costs. Selected stress budgets:
at least 30% lower median CPU draw-recording and scene GPU cost versus direct.
10b needs a further 5% median CPU recording win to replace instancing by default.

All times below are milliseconds, p50/p95/p99.

| Mode | Draws | CPU frame | CPU draw recording | Scene GPU |
|---|---:|---|---|---|
| direct | 4096 | 2.484/5.019/6.488 | 1.758/3.519/5.093 | 0.246/0.248/0.252 |
| instanced | 1 | 1.474/1.872/2.517 | 0.772/1.062/1.230 | 0.147/0.151/0.165 |
| indirect | 1 | 1.471/1.722/1.960 | 0.769/0.958/1.101 | 0.143/0.145/0.154 |

The stress gate passes. Indirect has essentially the same median CPU cost as
instancing, so it remains opt-in. Captures, CSV and summaries are retained in
