## Scope and contract

The 10a/b implementation stays inside `VulkanMeshRenderer`, its offline Slang shaders
and the existing mesh fixture. It merges adjacent compatible opaque mesh/material
items, preserving submitted order even for equal-depth surfaces. Shadow grouping
follows the existing caster/range/frustum filters. Transparent, overlay and
viewmodel draws remain individually ordered. CPU world culling and inspector
picking retain their owners; original temporal correspondence crosses batching
explicitly. Single-object draws use the existing push-constant transform path.
Passes without adjacent geometry bypass CPU instance staging.

Two scene slots own mapped instance/indirect buffers and wait for final GPU use
before reuse/growth. The shared record is 128 bytes with checked host offsets;
limits, byte ranges and command counts are checked. CPU writes are flushed before
submission. Indirect submission uses one `VkDrawIndexedIndirectCommand` per
compatible batch, zero `firstInstance`, and a push-constant storage offset. It
requires neither multi-draw nor indirect-first-instance features. Geometry
packing, bindless and GPU command generation are outside this patch. Runtime
controls are owned by [RENDERING](../RENDERING.md#scene-submission--vk14-10ab).
The [Vulkan indirect-draw contract](https://docs.vulkan.org/refpages/latest/refpages/source/vkCmdDrawIndexedIndirect.html)
provides the command/feature constraints.

## VK14-10c implementation — 2026-10-13

**Implemented; local parity and geometry-stress gates pass; opt-in.** Executed
2026-10-13–14. Source
base `c2ed759`. The owner explicitly selected the full implementation after the
initial evaluation. The current [technique/fallback contract](../RENDERING.md#scene-submission--vk14-10abc)
is authoritative. Occlusion, LOD, geometry packing, bindless and multi-draw remain
outside this bounded frustum-culling slice.

The offline `scene_culling.slang` consumer classifies bounds, performs stable
64-lane block scans and generates indexed commands. Each workgroup owns one
batch's reserved instance span: surviving records keep order and original
temporal correspondence, while later batches keep their own offsets. Shadows
use their actual pass projections. One slot-owned compute command buffer is
submitted before scene draws under the same timeline token. Output visibility
is synchronized to vertex/indirect reads and diagnostic copies. The renderer's
resolution timestamps include culling when enabled. Pipeline reload stages the
compute replacement with the existing pipelines and retains the working set on
failure. Existing world culling and inspector/picking ownership are preserved.

Host offsets/strides are asserted; `spirv-val --target-env vulkan1.4` passes and
disassembly confirms 128/48/20-byte instance/batch/indexed-command strides.
Storage range, record/command counts and dispatch-X limits are checked; command
readback verifies index counts, surviving-instance bounds and zero base fields.
The implementation follows the Vulkan [indirect-draw](https://docs.vulkan.org/refpages/latest/refpages/source/vkCmdDrawIndexedIndirect.html)
and [synchronization](https://docs.vulkan.org/spec/latest/chapters/synchronization.html)
contracts without adding optional draw features or another queue.
