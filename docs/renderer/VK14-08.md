# VK14-08 — temporal and resolution

Scope/status belongs to the [renderer plan](../RENDERER_MODERNIZATION_PLAN.md).
The owner selected full 08a–c and FSR evaluation on 2026-10-13.

## Selected contract

Opt-in TAA resolves scene-linear HDR with an eight-sample Halton jitter,
unjittered previous-minus-current top-down UV velocity, depth/normal/eligibility
rejection and neighborhood color clamping. Explicit previous transforms are
required; unknown-motion enemies, overlays, transparents and the first-person
weapon use unjittered draws and reject accumulation. UI is excluded from history.
Cuts, scene restore/respawn, resize, FOV, exposure, render-scale changes and
successful reload reset history; failed staged reload retains the working set.

08b selects a bounded Catmull-Rom spatial upscaler after the internal-resolution
temporal resolve. It is not TAAU or FSR. Tone mapping, grain and both UI backends
operate at native display resolution. TAA and resolution scaling require the
existing hardware-sRGB/internal-HDR path; defaults retain rendering unchanged.

08c is conditional on measured GPU pressure. Before enabling it, compare native
and scaled optimized real-map workloads, record scene GPU distributions and
transition costs, and require a stable bounded controller driven by completed
GPU timestamps rather than CPU frame time. No dependency or frame generation
is authorized by the FSR evaluation alone.

Local budgets selected before measurements: 1920×1080 RTX 4060 Ti, TAA resolve
GPU p99 <1.5 ms, native combined effects plus TAA scene p99 <16.67 ms. At a
GPU-pressure resolution, scaled scene p50 must improve relative to native;
record p95/p99, memory and controller transition tails separately. Animated
fixtures must cover camera/object movement, disocclusion, thin geometry,
unknown-motion enemies, viewmodel, transparency and cuts; still images alone
do not establish temporal quality. Technical image inspection does not replace
owner art acceptance or other-GPU testing.

Current and retained unjittered camera matrices plus their jitter offsets define
both raster projections. The input shader cancels current jitter from velocity;
resolve/debug reprojection adds previous-minus-current jitter separately. Each
history sample requires eligible previous bilinear taps, matching view depth and
normal; current neighborhoods containing an ineligible draw reject accumulation.
The RGB history is clipped to the current 3×3 range; history weight decreases
from 0.9 to 0.5 with motion. Background/silhouette and unknown-motion rejection
can retain aliasing; the spatial mode cannot reconstruct missing detail. At
reduced resolution the unjittered weapon is spatially upscaled with the scene.

`[render]` controls: `taa_enabled` (false), `render_scale` [0.5,1] (1),
`dynamic_resolution_enabled` (false), `dynamic_resolution_target_ms` [4,50]
(16.67). Player settings persist the first three and expose menu controls;
the authored target remains the scene-time budget. Selecting SDR disables TAA,
dynamic resolution and scaling. `RELAYCORE_VULKAN_PASS_INPUT_VIEW=temporal_source`
displays the unfiltered jittered source for comparisons and requires TAA.

Dynamic mode is justified by the 4K workload below. Two frame-local timestamp
pools measure shadows through tone mapping; results are read only after existing
scene completion, without a new host/query wait. Missing graphics timestamps
fail the requested mode explicitly. The controller filters samples, ignores
completions from older scales, changes by at most 0.05 per 32 matching samples,
and uses 1.05/0.8 budget hysteresis between the 0.5 floor and authored ceiling.
UI stays native; extent-dependent scene/input/bloom targets are replaced after
their final use and invalidate temporal history. Transition costs are measured
separately because target allocation and draining are not free.

## FSR evaluation — 2026-10-13

[AMD SDK 2.3.0 README](https://github.com/GPUOpen-LibrariesAndSDKs/FidelityFX-SDK)
lists temporal 2.3.4, upscaler 3.1.5, ML upscaler 4.1.1 and frame generation
3.1.6, while its known-issues table states Vulkan is currently unsupported.
Older [FSR 3.1.4 documentation](https://gpuopen.com/manuals/fidelityfx_sdk/techniques/super-resolution-interpolation/)
describes a Vulkan implementation; that is not proof for the current SDK.
The [standalone FSR2 repository](https://github.com/GPUOpen-Effects/FidelityFX-FSR2)
has Vulkan source and an MIT license. Its temporal input requirements include
motion/depth, jitter, exposure and reactive/transparency policy.

Decision: defer FSR integration. The current SDK cannot be treated as a tested
Vulkan dependency, and the old Vulkan option still requires genuine moving-object
correspondence and reactive inputs rather than this milestone's conservative
rejection. A future integration must pin a supported release, keep AMD types
renderer-local, validate dynamic content and compare quality/cost against the
native TAA and spatial modes. Frame generation remains separate, with its own
presentation/latency/UI contract. No FSR code, package or dependency is added.

### Quality evidence and limits

Animated real-map camera/shotgun sequences and checker comparisons are retained
in `build/msvc-debug/tests/vulkan-mesh-captures/`; matching GIFs and inspected
`g019-temporal-final.png`, `checker-final.png`, `settings-effects-final.png`
are in `build/vk14-08/`. The workshop grated floor and equipment are steadier
with native TAA; 67% rendering visibly loses fine texture/sign and weapon detail.
The weapon remains unjittered and does not accumulate history. The scrollable
settings menu exposes all new controls and Save without overlap.

The selected implementation deliberately rejects unknown motion, transparent
and overlay neighborhoods instead of inventing object velocities. Fine edges,
disocclusion and silhouette aliasing can remain; reduced resolution softens the
scene and weapon. Technical fixtures and image inspection do not establish
owner art/playthrough acceptance. Other-GPU and physical HDR display coverage
remain untested. DRS target replacement can hitch under 4K GPU pressure; its
steady-frame and transition distributions are reported separately above.

Changed ownership: `engine_config` owns strict authored controls;
`vulkan_mesh_renderer` / `render_resolution` own targets, temporal resolve,
queries and control; `temporal.slang`, `pass_inputs.slang` and
`tone_mapping.slang` own shader work. Game settings/menu/reload persist the
selections, and CMake owns offline shader/staging registration. Corresponding
config/controller/settings, UI and mesh graphics fixtures protect the contracts.
Changed C++ passes `clang-format --dry-run --Werror`; `git diff --check` passes.
Local documentation link targets were checked. The renderer-plan row records
08a–c implementation and FSR evaluation, with quality and allocation-tail limits;
no VK14-09 work is started.
