## 05b — shared pipeline cache

`VulkanDevice` owns one cache shared by mesh/shadow, tone mapping, RmlUi and
ImGui pipeline creation. Its lifetime covers every consumer. Existing atomic
shader publication and GPU completion waits remain the reload contract.

The runtime loads `vulkan-pipelines.cache` from the SDL application preference
directory before creating pipelines and saves it on renderer shutdown. Persistence
is optional: missing, unreadable, truncated, corrupt or incompatible data leaves
the live cache usable. The bounded file contains a schema, vendor/device/driver,
pipelineCacheUUID, a fingerprint of sorted SPIR-V filenames/content, payload size
and checksum. The Vulkan header is independently checked before driver ingestion.
No detailed filesystem work occurs during normal frames. A failed write is logged;
an interrupted write is rejected on the next load.

The pipeline fixture exports compiled pipelines, imports into a new device,
compares existing mesh/pass reference images, then mutates schema, vendor, device,
driver, UUID, shader fingerprint, length, checksum and payload. It also tests
truncation, changed SPIR-V and a missing file, followed by another successful render.
Successful/failed mesh and shadow reload tests remain in this fixture; HDR reload
and both UI pipeline consumers are covered by their existing graphics fixtures.

## 05c — capability-driven depth formats

Scene preference: D32_SFLOAT, X8_D24_UNORM_PACK32, D16_UNORM. Shadow preference:
X8_D24_UNORM_PACK32, D32_SFLOAT, D16_UNORM. Selection queries optimal-tiling
features and exact image usage/sample counts; sampled shadows additionally require
linear filtering, transfer source/destination and at least 48 array layers.
Allocated shadow extents/layers are checked against the selected format's limits.
No stencil formats or new depth conventions are introduced. Chosen formats are
shared by target allocation and pipeline rendering declarations. Shadow readback
decodes float32, packed24 or normalized16 to the existing float result contract.
An explicit native preferred format enables reproducible candidate fixtures and
fails if incompatible; this is not an authored/game setting or silent fallback.

`graphics.depth_formats` compares each supported scene candidate at 1x/4x MSAA,
and each sampled shadow candidate at 1x, against automatic selection. It requires
visible shadow geometry, finite normalized depth, mean RGBA delta <=0.5 for scene
depth or <=1.5 for shadow depth, and max depth delta <=2/65535 (two D16 steps).
Unsupported candidate rejection is an expected exercised branch, not a skipped
graphics test. Images are retained as `tests/vulkan-mesh-captures/depth-*.bmp`
inside the configured build. Existing shadow/MSAA/HDR image fixtures cover the
preferred formats and the original pass behavior.

Debug build and `ctest --preset graphics-debug -R
'^graphics.(depth_formats|msaa|hdr_pipeline|point_shadow_receiver)$'
--output-on-failure --no-tests=error --output-junit vk14-05c.xml` passed **4/4**,
zero skips/failures, 6.15 s. Report: `build/msvc-debug/vk14-05c.xml`.
On RTX 4060 Ti all three candidates executed: scene images were identical at
1x/4x; shadow mean RGBA delta was 0 for D32/D24 and 0.00000542535 for D16.

## 05d — surface-loss recovery and terminal device loss

Acquire/present `VK_ERROR_SURFACE_LOST_KHR` suspend that frame and request recovery
on the next drawable frame. Recovery drains acquire/render/present fences,
destroys the old swapchain, destroys/recreates the SDL surface, checks the selected
queue's present support and builds a swapchain without an old-surface handle.
Minimized/hidden windows defer recovery. Bootstrap surface-loss results during
swapchain creation similarly request a retry. Other recreation failures keep
presentation stopped until an explicit retry; incompatible present queues require
application restart/device selection. Device loss stops submission and explicit
recreation with a named error and restart instruction; there is no hot recovery.

The existing present-fence lifetime is preserved. The Vulkan specification states
that present requests rejected with surface loss still enqueue their semaphore
waits ([vkQueuePresentKHR](https://docs.vulkan.org/refpages/latest/refpages/source/vkQueuePresentKHR.html));
maintenance present fences protect their retirement. No normal-frame device-idle
wait was added.

`graphics.surface_loss` injects acquire failure before Vulkan acquires/signals, and
present failure after a real enqueue. Each of two window cycles performs three
acquire/present loss pairs, real SDL surface reconstruction, queue-support and
presented client-pixel checks, then resize/minimize/restore/hide/show and 120
stable frames. It also injects device loss and verifies that recreation is refused.
This exercises error policy on functioning hardware; it does not claim a real
driver device removal or an incompatible second GPU. The narrow two-call Vulkan
dispatch seam exists for these deterministic WSI failure fixtures.

Debug build and `ctest --preset graphics-debug -R
'^graphics.(surface_loss|vulkan_presentation|vulkan_recreation_failure|vulkan_device|resource_preparation)$'
--output-on-failure --no-tests=error --output-junit vk14-05d.xml` passed **5/5**,
zero skips/failures, 21.71 s. Report: `build/msvc-debug/vk14-05d.xml`.
The loss fixture reconstructed the surface 12 times; both window cycles sustained
presentation after recovery. Host allocations returned to zero. No validation or
shutdown diagnostics. Formatting/diff checks pass. **05d local gate complete.**

## 05e — memory and retention telemetry

Optional `VK_EXT_memory_budget` is enabled when present and passed to VMA. Device
capabilities/logs distinguish driver budgets from VMA estimates without making the
extension mandatory. `VulkanDevice::memory_usage()` returns each heap's usage and
budget, device-local flag, allocation/block counts and bytes through VMA's heap
budget API; third-party statistic types do not escape this owner.
An explicit snapshot forces VMA's cached driver-budget refresh through
`vmaSetCurrentFrameIndex`; this call is deliberately outside the normal frame path.

Upload diagnostics count retained staging bytes/batches and upload retirements;
scene diagnostics count deferred resources; mesh diagnostics include retired
materials. Completed objects still retained until collection remain counted.
Snapshots do not collect, wait for GPU work or change resource ownership. The
Advanced Diagnostics `Vulkan memory` window refreshes only when the user presses
`Refresh GPU memory`, retaining the displayed snapshot between frames. Device heap
statistics cover the whole device, and scene retention/descriptor totals include
the active backend plus a distinct previous backend retained for presentation.
No detailed VMA snapshot or heap query was added to ordinary frames. Allocation
names and the buffer-allocation/memory-snapshot Tracy zones supplement existing
shadow/debug labels and pass/wait instrumentation.

Regression fixtures compare the heap allocation snapshot with real VMA allocation
and release, exact staging byte/batch counts while a graphics queue is blocked,
and pending upload/scene/material retirements before and after GPU completion.
These are ownership/retention checks, not performance claims.
