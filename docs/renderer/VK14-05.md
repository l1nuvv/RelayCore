## 05b — shared pipeline cache

`VulkanDevice` owns one cache shared by mesh/shadow, tone mapping, RmlUi and
ImGui pipeline creation. Its lifetime covers every consumer. Existing atomic
shader publication and GPU completion waits remain the reload contract.

The runtime loads `vulkan-pipelines.cache` from the SDL application preference
directory before creating pipelines and saves it on renderer shutdown. Persistence
is optional: missing, unreadable, truncated, corrupt or incompatible data leaves
the live cache usable. The bounded file contains a schema, vendor/device/driver,
pipelineCacheUUID, a fingerprint of sorted SPIR-V filenames/content, payload size
and checksum. The Vulkan header is independently checked before driver ingestion.
No detailed filesystem work occurs during normal frames. A failed write is logged;
an interrupted write is rejected on the next load.

The pipeline fixture exports compiled pipelines, imports into a new device,
compares existing mesh/pass reference images, then mutates schema, vendor, device,
driver, UUID, shader fingerprint, length, checksum and payload. It also tests
truncation, changed SPIR-V and a missing file, followed by another successful render.
Successful/failed mesh and shadow reload tests remain in this fixture; HDR reload
and both UI pipeline consumers are covered by their existing graphics fixtures.

### Measurements and verification

Before the change, three `graphics.mesh_pipeline` process runs took 3074.88,
1827.30 and 1862.72 ms (including CTest/startup/render/teardown). Logs:
`build/vk14-05/baseline-{1,2,3}.log`. These are not pipeline compile-only timings.
The updated fixture prints renderer construction and reload timings; construction
also includes textures, descriptors, shadow targets and uploads. Driver caches and
OS caching affect repeated runs, so no isolated compile/startup speedup is claimed.

Build wrapper: `build/vk14-05/build.ps1`, using the existing MSVC developer shell,
configured Debug tree, Vulkan SDK and matching `VCPKG_ROOT`. Graphics tests run on
the interactive desktop with core and synchronization validation and
`DISABLE_VULKAN_OBS_CAPTURE=1`. Sandbox attempts are not gates: one staged OBJ
lookup returned Access is denied. The first cache fixture also retained an open
input stream, preventing Windows mutation/deletion; that test bug was corrected.

Final 05b results: `graphics.mesh_pipeline` passed in 3.10 s, zero skips,
`build/msvc-debug/vk14-05b-final.xml`; `graphics.game_hud` passed in 7.46 s
outside the sandbox (`vk14-05b-retry.xml`); `graphics.hdr_pipeline` passed in
2.73 s (`vk14-05b.xml`). No validation warning/error or shutdown failure.
The final cache fixture reported construction 41.81 ms (fresh device), 21.35 ms
(imported cache) and 21.94 ms (same device after rejected data), with reload
10.20/9.82/13.00 ms. These samples establish execution, not a controlled speedup.
The rebuilt code has no compiler warnings from this patch. Formatting and
`git diff --check` pass. **05b local technical gate complete.**
