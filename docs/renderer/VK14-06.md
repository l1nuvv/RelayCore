## 06b/c contract — 2026-10-12

The existing compute tone mapper remains the production compute consumer. An
opt-in, single-sample geometry pass prepares world-space mapped normals and
positive view-space depth in RGBA32F, plus previous-minus-current top-down UV
velocity, expected previous view depth and correspondence validity in RGBA32F.
The last velocity component describes surface eligibility separately from the
frame's history-valid flag; reset frames use the current MVP for zero velocity.
Both current and previous pixel eligibility are required for reprojection.
Background and overlay/transparent/viewmodel sample-center coverage are invalid.
Sampling is nearest; these inputs are independent of scene MSAA and do not
encode resolved subpixel coverage. A filtering consumer must add its actual
edge/reactive policy. Normals share the production inverse-transpose and
normal-map/tangent logic. Depth is clip W for the existing perspective projection,
not nonlinear hardware depth or radial distance.

`RenderItem::previous_model_matrix` is explicit draw correspondence. Missing
previous transforms reject history; draw order, mesh pointers and entity reuse
are never inferred as identity. Authored stationary props/chunks supply their
current transform as previous. Dynamic enemies, animated props and viewmodels
use conservative rejection until their consumer supplies actual correspondence.
No temporal AA/filter, AO, bloom or other VK14-07/08 effect is introduced.

The first temporal consumer is a GPU diagnostic: reproject previous color only
where previous depth/normal match and UV/correspondence are valid. A red/green
view exposes rejection/acceptance. Current/previous view-projection and exposure
advance only after successful submission. Jitter is zero in this milestone, so
jittered and unjittered projections coincide; a future jittering consumer must
extend the contract explicitly. Projection/FOV, extent/render-scale, exposure,
scene-time rewind, successful shader reload and off/on changes invalidate
history. Scene activation/restore, respawn and editor camera jumps call explicit
reset; callers use the same reset for future teleports/cuts. Failed staged shader
reload retains working pipelines/history. UI is composed after diagnostics and
excluded from the two-slot color history.

`RELAYCORE_VULKAN_PASS_INPUT_VIEW` accepts `off` (default), `scene` (prepare inputs
without replacing scene color), `depth`, `normals`, `velocity`, `history`, or
`previous_color` (raw reprojected color, not a final HDR display transform).
Invalid values fail explicitly. Default rendering allocates no input/history
images or draw buffers. The diagnostic requires the exact sampled/transfer
RGBA32F attachment format support; unsupported hardware fails the requested
diagnostic explicitly while ordinary rendering remains available. All four
Slang entries compile offline at the existing SPIR-V 1.5 baseline and participate
in shader staging/cache identity.

Both slots retain input/color history until queue-ordered reads complete;
input passes match opaque/overlay/transparent culling and depth-write policy,
with blending disabled so conservative masks replace inputs. Synchronization2
covers raster → sampling, color → history copy and sampling →
reuse. Extent changes drain both slots before replacing history views. CPU
readback is allocated only when requested. Reload stages both input/debug
pipelines with the existing mesh/shadow/tone-mapping transaction.

Fixtures: analytic plane depth/normals, mapped mirrored/nonuniform normals,
stationary/camera/object motion, missing correspondence, background/disocclusion,
normal discontinuity, transparent/overlay/viewmodel rejection, both scene slots,
HDR/SDR, MSAA 1/4, odd/tiny extents, successful/failed reload and history resets.
Integration uses existing lifecycle, UI, HDR/MSAA/material and G-019 checks.

Performance fixture: same optimized 1920×1080 two-pass containment workload and
settings as 06a. Reuse the retained unchanged `9f926d7`/06a-after binary capture
(SHA-256 `08e0c51e83fac825869a846587c5880c159230c5f08ff7358d2903e9adac0819`)
as the pre-change baseline. Local diagnostic budgets selected before measurement:
pass-input GPU p50 <1 ms, p99 <1.5 ms; color-history copy p99 <0.3 ms. Compare
ordinary rendering separately; the diagnostic intentionally adds work and is
not enabled as a quality effect. No performance improvement is presumed.

## 06a contract — 2026-10-12

The first compute consumer is the existing HDR tone-mapping pass, after world,
viewmodel and MSAA resolve, before display-space UI. Slang compiles
`tone_mapping.comp.spv` offline with SPIR-V 1.5 and includes it in the existing
runtime shader manifest/staging/cache identity. No dependency or shader-profile
change, new queue, temporal state or optional effect is introduced.

The selected graphics queue must support compute and the mutable RGBA8 UNORM
target must support storage plus existing attachment/transfer usage. Otherwise
the existing fragment pass is selected. A diagnostic process override,
`RELAYCORE_VULKAN_DISABLE_COMPUTE_TONE_MAPPING=1`, exercises that raster path;
unset/0 selects compute when supported; other values fail explicitly.

Both techniques use the same display-mapping function. Compute writes encoded
display RGB/scene alpha through the UNORM storage view in 8x8 groups; the sRGB
attachment view excludes storage usage. The shader bounds-checks partial groups.
Synchronization2 covers attachment writes/resolve → compute sampling, storage
writes → UI/readback/presentation. Descriptors/targets remain independent for
the two existing scene slots; shader reload retains the staged replacement and
drain contract. There is no history to reset in 06a.

Fixtures: existing HDR CPU color reference, alpha/UI/reload/resize cases; new
1x1, 7x9, 319x181 and 641x359 prepared-frame full-image checks; MSAA and G-019
integration. The raster override must execute the same HDR gates.

Budget: the existing optimized `relaycore_containment_profile` workload,
1920x1080 with a resize stage, VSync off, HDR/hardware sRGB, audio on, same
shadows/scene settings and two passes of seven states. Retain a before/after
Tracy capture and scene images. Tone-mapping settled GPU p50 should stay below
0.15 ms and p99 below 0.30 ms on this RTX 4060 Ti fixture; a systematic frame
regression needs investigation. These are local budgets, not a second-GPU or
human gameplay gate. No speedup is presumed from using compute.
