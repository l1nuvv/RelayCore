# RelayCore / Null Meridian

Выбранный владельцем знак D, доработанный 2026-10-15. Оригинальная векторная
геометрия RelayCore: измерительная скоба, изолированный ромб и разорванная ось.
Основная пара — `#C4B477` / `#111814`; версия меню использует `#B4A06A`.

`null-meridian.svg` — основной оригинал 128 × 128. Отдельные оригиналы
`null-meridian-16.svg` и `null-meridian-24.svg` сохраняют просветы на малых
размерах; в версии 16 px центральное отверстие намеренно квадратное 2 × 2.
`relaycore-wordmark.svg` содержит контуры существующего
`assets/fonts/RobotoMono-Regular.ttf`, без внешней шрифтовой зависимости.

Воспроизведение: `node scripts/build-branding.cjs` с существующим `sharp`,
доступным через `NODE_PATH`. Результаты в `assets/branding/`:

- `relaycore-menu.bmp`: 256 × 256, прямой RGBA в BMP V4 с явной alpha-маской;
  используется меню RmlUi, включая паузу, настройки и экран результата.
- `relaycore.ico`: PNG RGBA кадры 16/24/32/48/64/128/256 с прозрачными углами;
  встраивается в RelayCore, Sandbox и обновлятор. SDL Windows выбирает встроенный
  значок приложения; форма обновлятора извлекает значок собственного EXE.
- `relaycore.png`: прозрачный знак 512 × 512; `relaycore-wordmark.png`:
  композиция с надписью на тёмном фоне для дальнейшего использования.

Wordmark PNG также встроен в обновлятор как ресурс шапки окна: рабочая копия
обновлятора сохраняет его при запуске из временной папки без внешних assets.

Runtime-файлы доставляются существующим `relaycore_demo_assets`; SVG-оригиналы
остаются в `content/`. В README проекта используется векторный wordmark.
Windows-ярлыки на новые EXE получают их встроенный значок; уже закэшированные
значки старых установок могут обновиться после перезапуска оболочки. Генератор
не создаёт ярлыки, не меняет пользовательский рабочий стол и не выпускает архив.

## Проверка интеграции — 2026-10-15

Собраны `relaycore_demo`, `relaycore_sandbox`, `relaycore_player_ui_graphics` и
`relaycore_updater_tests` через `demo-debug`; игра и Sandbox также собраны через
`demo-dev`. В каждом из трёх EXE обоих профилей проверены ресурсы значков:
семь размеров, попиксельное совпадение с утверждённым ICO. Runtime BMP/RML/RCSS
в обоих staged roots совпадают с исходными файлами.

Пройдены `ctest --preset graphics-debug -R '^graphics\.player_ui$'
--output-on-failure --no-tests=error` и `ctest --preset test-debug -R
'^relaycore\.updater$' --output-on-failure --no-tests=error`, без пропусков.
UI-тест проверяет цвет знака, прозрачный центр и зазор оси в GPU-readback,
а также существующие сценарии меню при 1280/1920/2560/800 px ширины. Реальные
кадры меню и отдельно отрисованная форма обновлятора визуально просмотрены.
Для съёмки формы её обработчик `Shown` отключён; загрузка и установка обновлений
не запускались.

Первый sandbox build завершился MSVC C1902; обычная среда Visual Studio собрала
те же цели. Sandbox-тесты упёрлись в доступ к моделям/временным папкам. Финальные
тесты выполнены вне песочницы с `DISABLE_VULKAN_OBS_CAPTURE=1` для несовместимого
OBS implicit layer; Khronos validation оставлен включённым. Общий фильтр
`VK_LOADER_LAYERS_DISABLE` не использован в успешном прогоне: его предупреждения
об отключении слоёв сами нарушали CTest gate.

Проверки кэша значков пользовательского рабочего стола/Start menu и выпуск
standalone-архива не выполнялись. `git diff --check` прошёл.
